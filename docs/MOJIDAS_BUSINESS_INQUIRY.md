# 法人向けプランの公開受付フォーム

法人向けページはトライアル申し込み専用です。法人向けプランの相談・問い合わせは一般の `contact-inquiries` で受け付けます。トライアル受付と同時に法人ドメインを無効状態で登録し、登録成功後に受付メールを送信します。有効化・アカウント作成は担当者が行います。

## 一般お問い合わせ

Webでは一般用と法人向け相談用の別フォームを用意します。法人相談（category=corporate）の法人・団体名はサーバーでも必須検証し、保存・確認メール・管理者通知に含めます。一般問い合わせには法人・団体名は不要です。

`contact.html` は `POST /api/mojidas/contact-inquiries` を利用します。お名前、メールアドレスと確認、お問い合わせ内容（必須、最大5000文字）を受け付けます。Gmail等の共用メールも利用可能です。保存先は `contactInquiries`、メール件名は一般お問い合わせ用です。送信元と管理者宛先、送信状態管理、CORS、回数制限は法人フォームと共通です。一般／法人の区別はサーバーのルート登録で固定し、リクエストの指定で法人の制限を解除することはできません。一般受付にトライアル項目やアカウント自動作成はありません。

Webの `business.html` から `POST /api/mojidas/business-inquiries` を呼びます。アプリの認証・クレジットAPIに変更はありません。

## 受付範囲

- トライアル開始日時（日本時間）は必須。`trialStartsAt` は `YYYY-MM-DDTHH:mm` で保存し、サーバーが1暦月後の `trialEndsAt` を計算します。翌月に同じ日がない場合は月末の同時刻。確認画面で開始日時と1か月有効の説明、双方へのメールで開始・終了日時を案内し、新規法人ドメインの有効期間にも適用します。一般／法人相談フォームには追加しません。
- 法人・団体名、担当者名、メールアドレス・確認、任意の内容（質問・トライアル希望等）。用件の選択項目は設けません。
- トライアルには「販売店（任意）」を追加。正規販売店から紹介された場合の販売店名を最大200文字・1行で受け付け、申込確認・保存・双方へのメールに含めます。空欄・項目省略も許可し、旧フォームの再送互換を維持します。入力された名称だけで販売店の割り当てや正規販売店の認定は行いません。
- 企業・団体の独自ドメインメールが必須。`modules/partners/domain_policy.js` の共用メール除外リストを使い、サブドメイン・大文字も含めサーバーで拒否します。この判定は法人性を保証せず、人が確認します。
- 受付と新規法人ドメインの登録は同一transaction。販売店self、プランtrial、状態suspended、有効期間あり、指定開始から1か月、組織名・連絡先は申込内容、備考は紹介販売店名（ある場合）。上限10時間・上限停止ありで保存し、個人残高やアカウントは変更しません。
- 同一受付IDの再送では登録を繰り返さず、管理者による有効化や備考編集も保持します。別IDで既存ドメインを申し込んだ場合は409で個別問い合わせへ案内し、既存設定・残高・実績を上書きしません。旧方式の受付を再送しても遡及登録はしません。
- 保存失敗では受付・ドメインとも作成せずメールも送りません。保存成功後、no-reply@mojidas.jpから申込者へ受付（利用開始前）を案内し、app@mojidas.jpへ申込内容と有効化待ちを通知します。配送失敗時は既存の宛先別再送制御を使用します。
- 販売店名がある申込は、受付データの `notes` に入力内容を保持したうえで「紹介販売店：○○」を追記します。新規法人ドメインの備考にも紹介販売店名を記載します。通知メールにも備考として記載し、再送で追記を重複させません。

## メールと設定

既存の `SENDGRID_API_KEY`、`SENDGRID_FROM_EMAIL`、Firebase Admin設定を維持してください。このフォームのFromはユーザー指定により `no-reply@mojidas.jp`（差出人名Mojidas）に固定します。SendGridで当該ドメイン／差出人を認証しておく必要があります。

`app@mojidas.jp` への管理者通知、申込者への受付内容確認を、宛先を共有しない別メールとして送ります。ユーザー入力はプレーンテキストのみ。SendGridの正常応答は送信受付であり、受信箱への到達を保証するものではありません。

## 永続化・再送

一般問い合わせ・法人相談・トライアルの管理者宛て通知は、Reply-Toに検証済みの申込者メールアドレスを設定します。Fromは`no-reply@mojidas.jp`のままで、管理者はメールソフトの返信操作で申込者へ返信できます。申込者宛て確認メールの返信先は変更しません。既送信メールの再送や書き換えは行いません。

`Mojidas/{MOJIDAS_FIRESTORE_ENV}/businessInquiries/{requestID}` に受付内容、作成日時、payloadハッシュ、各宛先の送信状態を保存します。アクセスはサーバーのAdmin SDKのみです。受付本文やメールアドレスはサーバーログへ出力しません。

- 同じUUID・同じ内容の再送は同じ受付を使います。異なる内容なら409。
- 送信状態は `pending → sending → accepted / failed / unknown`。transactionで宛先ごとに獲得し、並行送信を防止。
- 明確な4xx拒否・未設定はfailed。再操作ではfailed／pendingだけ再送します。
- タイムアウト、5xx、送信後の保存失敗は結果不明。プロセス終了時のsendingも含め自動再送しません。ユーザーに受付番号と問い合わせ先を案内します。管理者はFirestore・SendGridの記録を確認して対応してください。管理画面や自動再開ジョブは今回追加していません。
- 通常の送信でFirestoreは受付作成transaction1回、宛先獲得transaction2回、完了write2回、最終read1回。失敗時も受付内容を維持し、クレジット等には触れません。

## 防御と公開確認

- 許可Originは `https://mojidas.jp`、`https://www.mojidas.jp`、`https://app.mojidas.jp`。本番以外はHTTP localhost／127.0.0.1も許可。Originなし・nullは拒否。CORSはボット認証ではありません。
- JSONのみ、入力長・メール形式をサーバー検証、ハニーポット、1時間5回／IP（既存の信頼プロキシ設定に従うreq.ipを使用）。制限はプロセスメモリーのため複数プロセスでは共有されません。大量アクセスには配信基盤でのレート制限等も運用してください。
- Webとtoolsの両方をデプロイし、SendGrid差出人認証と実配送は公開前に別途検証してください。
- `npm run test:business-inquiry` はメール／DBを隔離fixtureに置換し、正常・不正入力、共用ドメイン拒否、CORS、回数制限、再送・部分失敗・結果不明・再読込を検証します。
