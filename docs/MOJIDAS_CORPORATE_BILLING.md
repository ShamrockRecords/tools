# 法人の月次請求（2026-10-29）

## 対象と計算

自社直販（`partnerID=self`）の従量制・ライト・スタンダードを対象とする。無料トライアル・販売店経由には発行しない。カスタムや標準と異なる利用枠は個別確認として自動発行を保留する。有料プラン同士の翌月変更予約は[法人ポータル](MOJIDAS_CORPORATE_PORTAL.md)に対応する。新規契約・停止・再開の操作は今回の対象外。

- 初回は2026年10月利用分を11月1日以降に発行する。日本時間の暦月で締め、毎日00:00 JSTに未発行の締め済み月を処理する。遅延・実行漏れがあれば次の実行で追いつく。
- 従量制は基本料金2,200円、ライトは基本2,200円＋プラン11,000円／50時間、スタンダードは基本2,200円＋プラン22,000円／100時間。税込。
- 開始・再開月は当日を含む残り暦日数／当月暦日数で基本料金・プラン料金・利用枠を日割りする。11月16日にライトを開始した場合は6,600円／25時間。
- 有料期間の月合計から利用枠を差し引き、残りの1分未満を切り上げて5.5円／分を乗じる。月額と合計した最後に1円未満を切り捨てる。中間値は整数による有理数演算とし、Stripeの整数円明細には必要に応じて端数調整行を加える。
- 集計時点は既存仕様どおりサーバーでの利用確定時刻。リアルタイムは各差分、ファイル・正式翻訳は完了の月へ計上する。音声内の時刻で月を分割しない。開始・再開前のトライアル等は有料期間の台帳集計に含めない。正式翻訳の50％換算は既存台帳で済んでいるため二重換算しない。
- ポータルの翌月変更予約は月初0時に契約履歴へ記録し、対象月ごとのプランで請求する。日次ジョブは請求前に予約を適用し、dry-runでも未適用の予約を参照して料金を試算する。
- 同じ月の有料プラン変更、即時停止・有効期限終了、停止と再開による空白、販売店移管は合意済みの計算方法がないため、その月を保留する。日付を推定して満額請求しない。前月以前から停止していた契約の月途中再開は日割り対象。

## 発行・支払い・通知

Stripe Invoicingの`send_invoice`で作成し、`auto_advance=false`、支払方法は`card`に限定する。自動引き落としは行わず、Stripeの請求メールから毎月お客様に支払っていただく。支払期限は発行月末23:59:59 JST。例：10月分を11月1日発行→11月30日期限。

発行済み請求は法人ポータルに対象月・税込額・内訳・期限・状態・PDF・支払いリンクを表示する。表示・リンク取得とも正式ログインと請求の`portalAccountID`を照合する。リンク取得時はStripeから最新URLを取得する。メール送付先は確定時の法人連絡先、閲覧権限は確定時のポータルアカウントへ固定し、後日の連絡先変更で過去請求を書き換えない。

期限を過ぎると「支払期限超過」と表示する。翌日のジョブでStripeの未払い状態を再確認し、同じ請求書を使って1回だけ支払い案内を再送する。ジョブ障害時は復旧後に1回送る。自動利用停止は行わない。管理者が既存の有効／無効操作で判断する。Stripeの自動督促は無効にし、別の運用ジョブから重複した催促を送らない。

既存の署名付きWebhook `/api/mojidas/billing/stripe/webhook`で以下を購読する。既存の個人向けCheckoutイベントも維持する。

```text
invoice.finalized
invoice.paid
invoice.payment_succeeded
invoice.payment_failed
invoice.payment_action_required
invoice.voided
invoice.marked_uncollectible
invoice.updated
invoice.sent
```

Webhook本文だけで支払済みにせず、Stripeで最新請求を取得し、請求ID・環境・Customer・通貨・金額・明細・支払期限を照合する。通知の再送や順序逆転で支払済み／取消を未払いに戻さない。日次ジョブでも未払い請求を同期する。

## 保存・再試行

`Mojidas/{MOJIDAS_FIRESTORE_ENV}`配下に次を保存する。クライアントからの直接書き込みは許可しない。

| コレクション | 内容 |
| --- | --- |
| `corporateBillingContracts` | ドメイン＋作成日時を識別子とした契約世代、設定変更履歴、履歴の確認開始時刻 |
| `corporateInvoices` | 契約世代＋対象月で一意の料金・利用量・宛先の確定記録、Stripe ID、状態、送信日時 |
| `corporateBillingOperations` | 外部操作のパラメーター、開始日時、結果ID、冪等キーの根拠 |

管理者の契約保存と履歴追加は同一transactionで行う。料金確定と月次集計の締めマーカーも同一transactionで保存し、利用確定と競合した場合は再試行する。月を越えた利用確定は新しい月へ計上する。利用台帳・月次カウンター・個人残高を削除・初期化しない。法人ドメインを削除しても契約履歴と確定請求は保持する。

請求書・明細・初回メール・督促それぞれに永続操作記録とStripeの冪等キーを使用する。最初の操作から23時間以上経過して結果が不明ならPOSTを再実行せず、Customer／Invoice／InvoiceItemのメタデータや`invoice.sent`イベントのリクエストキーで成功済み操作を照合する。一意に確認できれば続行し、見つからない・複数ある場合は`STRIPE_RESULT_REVIEW_REQUIRED`として保留する。[Stripeのキーは24時間経過後に削除され得る](https://docs.stripe.com/api/idempotent_requests)ため、古いキーの再利用だけでは二重発行を防げない。

保留時はログの契約・対象月と`corporateInvoices.lastError`、操作記録の`name/params`、Stripeのメタデータ・イベントを照合する。操作記録を削除して再発行しない。Stripe側に成功結果が残っていれば同じコマンドで再照合できる。成功／未実行を確定できないものや、未確定のまま発行月を越えたものは個別に確認してから復旧する。

## 初回導入とScheduler

必要な設定：既存の`FIREBASE_ADMIN_CREDENTIALS`（JSONまたはbase64）、`FIREBASE_PROJECT_ID`、`MOJIDAS_FIRESTORE_ENV`、`STRIPE_SECRET_KEY`、Web用`STRIPE_WEBHOOK_SECRET`。`MOJIDAS_CORPORATE_BILLING_FIRST_MONTH`の既定値は`2026-10`。Webとジョブは同じFirestore環境・Stripeモードを使用する。

`MOJIDAS_CORPORATE_TAX_RATE_ID`は任意。設定する場合はStripe側で有効な内税10％の税率を用意する。請求書ごとに税率IDを固定し、税込総額は変えない。未設定では税率別内訳を付けない。請求者名・住所・登録番号・メール設定等はStripe側で確認する。

既存の契約条件を過去へ推測適用しない。初回の手順は次のとおり。

1. サーバーを更新し、現在条件だけを記録する。メール・請求書は作成しない。
   `npm run mojidas:bill-corporate -- --record-contracts --execute`
2. 10月の開始日、プラン、停止・変更の有無を契約資料で確認する。最初に記録した条件が過去から継続している場合だけ、ドメインを指定して確認する。最初はdry-runで対象条件を表示する。
   `npm run mojidas:bill-corporate -- --domain company.example --confirm-history-from 2026-10-01`
3. 表示した条件が正しい場合、同じコマンドに`--execute`を追加して履歴を補完する。作成日より前へ遡らない。過去に別プラン・停止・移管がある場合、この補完コマンドを使わず個別に履歴を確認する。確定請求のある契約への補完は拒否する。
4. 11月1日以降、`npm run mojidas:bill-corporate -- --dry-run`で請求対象・金額・エラーを確認する。未確認の契約は保留として出力する。
5. Heroku Schedulerへ`npm run mojidas:bill-corporate -- --execute`をDaily、15:00 UTC（翌日00:00 JST）で登録する。毎日同じコマンドを使う。Webプロセス内のタイマーは不要。

[Heroku Scheduler](https://devcenter.heroku.com/articles/scheduler)の起動時刻は厳密ではないため、0時ちょうどの配信は保証しない。月末締めはJSTで判定し、締め前の月は処理しない。失敗はジョブログと終了コードで確認する。終了コード0はエラーなし、1は法人単位の保留／失敗あり、2は設定・引数・全体の失敗。既定動作はdry-runで、契約・請求・Stripe・メールへ書き込まない。
