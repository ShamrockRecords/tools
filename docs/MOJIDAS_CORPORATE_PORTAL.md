# 法人向けポータル（2026-09-21）

## 作成とログイン

- URL: `https://app.mojidas.jp/corporate`。法人ドメインを有効で追加、または管理者が無効から有効へ変更したとき、ドメインとポータル用アカウントを同じトランザクションで保存する。詳細編集による有効化も対象。
- トライアル申込は無効で保存し、有効化するまでポータルを作らない。登録済みドメインは、状態にかかわらず追加・トライアルの再申込を拒否し上書きしない。
- 初回有効化には連絡先メールが必要。保存後にURL・メールアドレス・仮パスワードをメール送信する。開始日が未来でも有効設定時にポータルは作成するが、アプリの利用期間判定は変更しない。
- メールアドレスをログインIDとする。Mojidasアプリ（Firebase Authentication）・販売店・管理者とは別の認証。同じ連絡先メールの複数ドメインは一つのポータルアカウントへ紐付ける。
- 初回は仮パスワード確認 → メールの6桁コード → 新しいパスワードの必須設定 → ダッシュボード。2回目以降のログインではコード送信しない。
- コードは10分・5回まで、再送は1分以上あける。再送で以前のコードは無効化し、一度使用したコードは再利用不可。初回の部分ログインは15分までで、メール認証だけではダッシュボードへ進めない。
- パスワードは12〜128文字。通常の変更には現在のパスワードが必要。変更時はアカウントのversionを更新し、他のログインセッションを無効化する。
- ログイン失敗5回でアカウントを15分ロック。接続元IPの認証操作にも15分15回の制限を設ける。

## 画面・権限

- ダッシュボードは自分に紐付く法人の組織名・ドメイン・プラン・利用状態のみ表示。ユーザーメニューはパスワード変更・ログアウト。
- 無効な法人もポータルで状態を確認できるが、法人利用を許可するものではない。プラン変更・停止予約・再開・請求・パスワード再発行は今回の実装範囲外。
- 連絡先の編集だけではログインIDや閲覧権限を移譲しない。管理者の詳細画面に作成時のログインメールを表示する。
- 既存ドメインの一括作成・一括メール送信はしない。既存の有効ドメインも管理者が保存すると未作成分のみ作成する。再有効化でパスワードを再発行しない。

## 保存とメール障害

- `Mojidas/{environment}/corporatePortalAccounts`（メールのSHA-256をID）、`corporatePortalChallenges`、ドメインの`portalAccountID`・`portalLoginEmail`・`portalCreatedAt`を使用。クライアント直アクセスは許可せずAdmin SDKから扱う。
- パスワードはscryptハッシュ。未送信の仮パスワードだけAES-256-GCM暗号化で保存し、送信成功または正式パスワード設定後に削除する。コードはHMACで保存し、使用後にハッシュを削除する。
- `SESSION_SECRET`は全インスタンス共通の固定値で32文字以上必須。未送信招待の復号にも使用するため、鍵変更前に未送信分を解消する。送信元は`MOJIDAS_AUTH_FROM_EMAIL`、未設定時`no-reply@mojidas.jp`。SendGridの認証済み送信元とAPIキーが必要。
- メール失敗時もドメイン・アカウントは保存済みとして明示する。管理者の詳細「ポータル案内を再送」で未送信分のみ再試行する。送信済み分には再送もパスワード再発行もしない。
- 60秒の送信リースで同時送信を抑制する。自動無限リトライはない。メール受付後のプロセス停止等では同じ案内が重複配信される可能性があるが、アカウントやパスワードは再作成しない。
- 専用Cookie `mojidas.corporate.sid`（Path `/corporate`）と独立した永続セッションを使用。正式ログインは30日（操作による延長なし）。POSTはCSRF検証、ログイン・パスワード変更時はセッションIDを再生成する。

## 検証

- `npm run test:corporate-portal`: 隔離DB・メール代替で有効化、重複拒否、保存失敗時のロールバック、メール再送、コード期限・上限・再利用拒否、強制パスワード変更、旧セッション失効、アカウントロック、権限分離、HTTPフローを確認する。
- `npm run test:business-inquiry`: トライアル登録・既存ドメイン拒否。
- 本番公開前にテスト用法人でSendGrid実配信、初回コード受信、パスワード変更、サーバー再起動後のログイン保持、別法人の非表示を確認する。本番データや実配信による試験は自動テストに含めない。
