# 法人向けポータル（2026-09-21）

## 作成とログイン

- URL: `https://app.mojidas.jp/corporate`。法人ドメインを有効で追加、または管理者が無効から有効へ変更したとき、ドメインとポータル用アカウントを同じトランザクションで保存する。詳細編集による有効化も対象。
- トライアル申込は無効で保存し、有効化するまでポータルを作らない。登録済みドメインは、状態にかかわらず追加・トライアルの再申込を拒否し上書きしない。
- 初回有効化には連絡先メールが必要。保存後にURL・メールアドレス・仮パスワードをメール送信する。開始日が未来でも有効設定時にポータルは作成するが、アプリの利用期間判定は変更しない。
- メールアドレスをログインIDとする。Mojidasアプリ（Firebase Authentication）・販売店・管理者とは別の認証。同じ連絡先メールの複数ドメインは一つのポータルアカウントへ紐付ける。
- 初回は仮パスワード確認 → メールの6桁コード → 新しいパスワードの必須設定 → ダッシュボード。2回目以降のログインではコード送信しない。
- コードは10分・5回まで、再送は1分以上あける。再送で以前のコードは無効化し、一度使用したコードは再利用不可。初回の部分ログインは15分までで、メール認証だけではダッシュボードへ進めない。
- パスワードは12〜128文字。通常の変更には現在のパスワードが必要。変更時はアカウントのversionを更新し、他のログインセッションを無効化する。
- ログイン失敗5回でアカウントを15分ロック。接続元IPの認証操作にも15分15回の制限を設ける。

## 画面・権限

- ダッシュボードは自分に紐付く法人の組織名・ドメイン・プラン・利用状態、利用集計、料金概算とアカウント管理を表示。ユーザーメニューはパスワード変更・ログアウト。
- 無効な法人もポータルで状態を確認できるが、法人利用を許可するものではない。プラン変更・停止予約・再開・請求・パスワード再発行は今回の実装範囲外。
- 連絡先の編集だけではログインIDや閲覧権限を移譲しない。管理者の詳細画面に作成時のログインメールを表示する。
- 既存ドメインの一括作成・一括メール送信はしない。既存の有効ドメインも管理者が保存すると未作成分のみ作成する。再有効化でパスワードを再発行しない。

## 保存とメール障害

- `Mojidas/{environment}/corporatePortalAccounts`（メールのSHA-256をID）、`corporatePortalChallenges`、ドメインの`portalAccountID`・`portalLoginEmail`・`portalCreatedAt`を使用。クライアント直アクセスは許可せずAdmin SDKから扱う。
- パスワードはscryptハッシュ。未送信の仮パスワードだけAES-256-GCM暗号化で保存し、送信成功または正式パスワード設定後に削除する。コードはHMACで保存し、使用後にハッシュを削除する。
- `SESSION_SECRET`は全インスタンス共通の固定値で32文字以上必須。未送信招待の復号にも使用するため、鍵変更前に未送信分を解消する。送信元は`MOJIDAS_AUTH_FROM_EMAIL`、未設定時`no-reply@mojidas.jp`。SendGridの認証済み送信元とAPIキーが必要。
- メール失敗時もドメイン・アカウントは保存済みとして明示する。管理者の詳細「ポータル案内を再送」で未送信分のみ再試行する。送信済み分には再送もパスワード再発行もしない。
- 60秒の送信リースで同時送信を抑制する。自動無限リトライはない。メール受付後のプロセス停止等では同じ案内が重複配信される可能性があるが、アカウントやパスワードは再作成しない。
- 専用Cookie `mojidas.corporate.sid`（Path `/corporate`）と独立した永続セッションを使用。正式ログインは30日（操作による延長なし）。POSTはCSRF検証、ログイン・パスワード変更時はセッションIDを再生成する。

## アカウント管理と利用状況（2026-09-29）

- 法人ドメインと対象月を選択し、合計・認識種別ごとの利用時間、上限、超過、料金概算を表示。トライアルは有効期間全体、それ以外は選択した日本時間の暦月で集計する。利用台帳は読取のみで、個人残高・既存利用実績は更新しない。
- アカウントはFirebase Authの現在のメールドメインと完全一致するものだけ。メールアドレス部分一致検索、50件単位のページ送り、個別・最大100件の一括有効無効。アカウント別の利用時間も同じ期間で表示する。旧台帳のuserID欠落は元の法人予約から補完し、削除済み等の紐付け不能分は合計に残して別記する。新しい法人台帳にはuserIDも記録する。
- 「新しくログインしたアカウントの扱い」の「自動で有効にする」チェックで変更・自動保存する（DOM更新、CSRF・法人所有権検証あり）。初期値はオン。オフなら新規アカウントは無効で一覧に追加され、管理者が後から有効にできる。初回の法人判定または一覧への初回掲載時に、現在の設定をトランザクションで`corporateMembers`へ固定する。チェック変更や再ログインは既存状態を変更しない。domain・userID・enabled・日時を保存し、個別変更時は操作者も保存する。IDはdomainとUIDのSHA-256。メールや認証情報を複製しない。
- 無効化は法人プランの対象解除であり、Firebase Authの無効化・ログイン禁止は行わない。新規の認識は個人枠へ戻る。開始済みの法人処理は次の確認・報告で停止し、受信済み利用は法人として精算する。途中で個人枠へ付け替えない。停止までには報告間隔分の遅れがある。終了精算・再送は引き続き受け付ける。
- 正式ログイン済みのポータルアカウントのみ操作可能。CSRFとドメイン所有者を検証し、各UIDの現在のメールドメインもサーバーで照合する。一括処理は全件検証後に同じtransactionで保存し、他社混入や失敗時は全件変更しない。Authのメール認証・アカウント停止・法人契約の有効期間など既存の利用条件は別途維持する。
- アプリのアカウント削除ではそのUIDの個別設定を削除し、法人ドメイン削除ではそのドメインの個別設定も同時に削除する。他のUID・ドメインを変更しない。
- 料金はWebの現行料金表に基づく参考額。税込月額は従量制2,200円、ライト13,200円、スタンダード24,200円。月合計の超過を分単位に切り上げて5.5円／分を加算し、円の小数は保持する。トライアルは0円。カスタムの月額と合計は個別契約として未計算。確定請求・Stripe課金・契約更新は行わない。過去月も現在のプランで試算する旨を明記し、当時の請求額と誤認させない。月途中の基本料金の日割りは未確定のため含めない。
- 検索時はサーバー側でAuthを列挙して対象ドメインに限定し、その後検索・ページ分割する。全体件数に応じてAuthの読取りが増える。専用索引への移行は今後の規模に応じて検討。法人利用台帳の既存複合インデックスを使用し、新規の複合インデックスや環境変数は不要。

### 追加の検証

- `npm run test:corporate-portal`で個別・一括操作、手動／自動、他法人拒否、CSRF、検索・ページ送り、保存失敗、旧台帳、認識中の対象解除と最終精算、料金概算を隔離データで検証する。
- `CORPORATE_PREVIEW=1 node tests/mojidas_corporate_management.test.js`はループバックだけの隔離プレビュー。出力URLへ任意のダミー認証情報で入れる。本番Auth・Firestore・メールは使用しない。終了はCtrl+C。
- ローカルブラウザーでは一括有効化、個別無効化、メール検索、自動有効化設定の保存とレイアウトを確認済み。本番デプロイ・実アプリでの確認は別途必要。MacとWindowsそれぞれで、テストアカウントを無効にしてもログインでき、新規利用が個人枠になり、再有効化後は法人枠になることを確認する。認識中の解除では次の報告で停止し、個人残高が途中消費されないことも確認する。

- `npm run test:corporate-portal`: 隔離DB・メール代替で有効化、重複拒否、保存失敗時のロールバック、メール再送、コード期限・上限・再利用拒否、強制パスワード変更、旧セッション失効、アカウントロック、権限分離、HTTPフローを確認する。
- `npm run test:business-inquiry`: トライアル登録・既存ドメイン拒否。
- 本番公開前にテスト用法人でSendGrid実配信、初回コード受信、パスワード変更、サーバー再起動後のログイン保持、別法人の非表示を確認する。本番データや実配信による試験は自動テストに含めない。
